# Как ChatGPT и Codex работают с сайтом через GitHub

## Где что лежит

| Репозиторий | Доступ | Что внутри |
|---|---|---|
| `rssmp-3d-tour/rssmp-site` | открытый (временно) | Исходники, документы, тесты, скиллы. Здесь ИИ вносит изменения. Отчёта аудита и черновиков медицинских текстов в нём нет |
| `rssmp-3d-tour/rssmp-3d-tour.github.io` | публичный | Только готовая сборка `dist` — то, что видят посетители https://rssmp-3d-tour.github.io |

ИИ правит исходники в `rssmp-site`. Опубликованную сборку вручную не меняют: её каждый раз собирает `build_pages.py`.

## 1. Подключите GitHub к ChatGPT

Названия пунктов меню у OpenAI меняются. Ниже — порядок действий по моим данным; если пункт называется иначе, ищите по смыслу.

1. ChatGPT → **Настройки → Приложения** (Apps / Connectors) → **GitHub** → **Подключить**.
2. На странице GitHub разрешите доступ **только к репозиторию `rssmp-site`** (Only select repositories).
3. После этого в чате можно попросить: «Открой репозиторий rssmp-3d-tour/rssmp-site, прочитай AGENTS.md и ПЕРЕДАЧА_ПРОЕКТА.md».

## 2. Codex — для доработки сайта

Codex — агент OpenAI для кода. Он сам вносит изменения в репозиторий и открывает pull request.

1. Откройте https://chatgpt.com/codex и подключите GitHub, если он ещё не подключён.
2. Создайте окружение (environment) для `rssmp-3d-tour/rssmp-site`. В скрипт установки (setup script) впишите:

   ```bash
   cd tests && npm ci && npx playwright install --with-deps chromium
   ```

   С ним Codex сможет запускать проверки сам. **Не проверено** — работает ли установка в окружении Codex. Если не заработает, проверки всё равно выполнит GitHub Actions (п. 3).
3. Поставьте задачу обычным языком, например: «Добавь в карточку точки тура кнопку „Подробнее в справочнике“». Codex прочитает `AGENTS.md`, внесёт изменения в отдельной ветке и откроет pull request.

## 3. Как принимать изменения

1. Откройте pull request в `rssmp-site`.
2. Внизу дождитесь проверки **«Сборка и проверки»**. Зелёная галочка — всё прошло (около 10–15 минут). Красный крестик — попросите Codex исправить: он видит, что упало.
3. На вкладке **Files changed** посмотрите изменения. В описании pull request агент перечисляет, что проверено, а что нет.
4. Если всё устраивает — **Merge pull request**.

## 4. Как опубликовать новую версию

Публикуете вы сами — живой сайт не меняется без вашего решения.

1. В `rssmp-site` откройте **Actions** → последний запуск на ветке `main` с зелёной галочкой.
2. Внизу, в разделе **Artifacts**, скачайте:
   - `rssmp-github-pages` — для GitHub Pages;
   - `rssmp-beget` — для Beget.
3. Распакуйте архив и загрузите **содержимое**:
   - на GitHub Pages — по `GITHUB_PAGES.md`, раздел «Обновление сайта»;
   - на Beget — по `BEGET.md`, с полной заменой `public_html`.
4. Сверка: `python3 check_deploy.py https://rssmp-3d-tour.github.io` — все строки `SAME`.

Автоматическая публикация после слияния **не настроена**. Её можно сделать через GitHub Actions и токен с правом записи в репозиторий сайта. Но тогда каждое слияние сразу меняет живой сайт. Решение за вами.

## Безопасность

- Давайте ChatGPT и Codex доступ только к `rssmp-site`. Доступ к `rssmp-3d-tour.github.io` им не нужен.
- Не пересылайте в чат пароли и токены.
- Пока `rssmp-site` открытый, не добавляйте в него отчёт аудита (`AUDIT_REPORT.md`), черновики медицинских текстов и заметки с вопросами к юристу: они перечислены в `.gitignore` и хранятся у владельца. Когда репозиторий станет приватным, их можно вернуть.
