# Передача проекта РССМП для полного аудита и доработки

## 1. Задача для Claude

Проведи полный технический, функциональный, визуальный, текстовый, архитектурный, безопасностный и доступностный аудит сайта Республиканской станции скорой медицинской помощи в Грозном. После аудита исправь подтверждённые ошибки по приоритетам, не разрушая уже работающие функции.

Не начинай с полного переписывания проекта. Сначала изучи исходники, собери сайт, воспроизведи проблемы, составь таблицу дефектов с доказательствами и только затем вноси исправления небольшими проверяемыми этапами.

Сайт предназначен для публичного показа жителям, сотрудникам станции и комиссии. Требуемый характер оформления: официальный, спокойный, современный и качественный сайт медицинского учреждения, без рекламного пафоса и визуальных признаков шаблонного «AI-дизайна».

## 3. Структура проекта

```text
build_pages.py          Генератор всех HTML-страниц и поискового индекса
shell.html              Общая оболочка: head, шапка, навигация, подвал, диалоги
home.html               Содержимое главной страницы
beget.htaccess          Исходник конфигурации Apache/Beget
BEGET.md                Инструкция по сборке и публикации
CLAUDE_HANDOFF.md       Этот документ
dist/                   Готовый сайт для загрузки в public_html
  .htaccess
  index.html
  404.html
  style.css
  app.js
  tour-viewer.js
  search-index.json
  robots.txt
  favicon.svg
  assets/
  about/index.html
  patients/index.html
  news/index.html
  tours/index.html
  gallery/index.html
  contacts/index.html
  privacy/index.html
```

Важная особенность: `build_pages.py` генерирует HTML, `search-index.json`, `robots.txt`, `sitemap.xml` и копирует конфигурацию `.htaccess`. Файлы `dist/style.css`, `dist/app.js`, `dist/tour-viewer.js` и изображения сейчас являются редактируемыми исходниками внутри `dist`, а не результатом отдельного JS/CSS-сборщика.

## 4. Сборка

Демонстрационная сборка, закрытая от индексации:

```bash
python3 build_pages.py
```

Публичная сборка после утверждения домена и материалов:

```bash
RSSMP_PUBLIC=1 RSSMP_BASE_URL=https://ПОДТВЕРЖДЕННЫЙ-ДОМЕН python3 build_pages.py
```

Без `RSSMP_PUBLIC=1` сайт намеренно создаёт `robots.txt` с `Disallow: /`. Не включай индексацию до согласования текстов, фотографий, юридических сведений и домена.

Базовые проверки:

```bash
node --check dist/app.js
node --check dist/tour-viewer.js
git diff --check
```

Для локального просмотра нужен HTTP-сервер: абсолютные пути `/assets/...` и `/search-index.json` не рассчитаны на открытие страниц через `file://` или на публикацию в подпапке сайта.

## 5. Что уже реализовано

### Общий сайт

- Восемь маршрутов: главная, о станции, пациентам, новости, 3D-туры, галерея, контакты, конфиденциальность.
- Собственная страница 404.
- Адаптивная шапка и мобильное меню.
- Номер вызова скорой помощи `103` в шапке, на главной и в подвале.
- Раздел для пациентов с номерами `103` и `112` и памяткой для разговора с диспетчером.
- Контакты, копирование адреса и переход к карте.
- Поиск по локальному `search-index.json`.
- Настройки увеличенного текста, контрастности и отключения анимации; сохраняются только в `localStorage` браузера.
- Фильтрация новостей.
- Галерея с нативным диалогом, листанием кнопками и клавишами.
- Нативные диалоги поиска и настроек.
- Анимация логотипа и появления контента с учётом `prefers-reduced-motion`.
- Системные шрифты без внешних CDN.
- Нет форм регистрации, личного кабинета, рекламы, аналитики и внешнего JavaScript.

### Безопасность и сервер

В `.htaccess` настроены:

- запрет листинга каталогов;
- собственная 404;
- `X-Content-Type-Options: nosniff`;
- `X-Frame-Options: DENY`;
- `Referrer-Policy`;
- `Permissions-Policy` для камеры, микрофона, геолокации, гироскопа и WebXR;
- Content Security Policy с локальными скриптами и изображениями;
- сжатие поддерживаемых текстовых форматов;
- отключение кэширования HTML, JSON, CSS и JS на этапе разработки;
- недельное кэширование изображений.

### 3D/360/VR

- Собственный WebGL-панорамный просмотрщик без сторонних библиотек.
- Два типа автомобилей: класс B и класс C.
- Для каждого автомобиля предусмотрены внешний вид и медицинский салон: всего четыре логические сцены.
- Переключатели автомобиля и вида «Снаружи / Внутри».
- Перетаскивание мышью и пальцем, масштаб колесом, клавиатурные стрелки и `+/-`.
- Полноэкранный режим.
- Автоматический обзор.
- Гироскоп на совместимых мобильных устройствах.
- WebXR на совместимых VR-гарнитурах.
- 23 интерактивные точки с описаниями и переходами между внешней и внутренней сценами.
- Озвучивание описания через Speech Synthesis браузера.
- Обработка потери контекста WebGL и ошибок загрузки текстуры.
- Исправление ориентации панорамы: прямое сопоставление UV и `UNPACK_FLIP_Y_WEBGL=false`.
- Режим присутствия, подписанный в интерфейсе как «5D-режим»: пространственно панорамируемый синтезированный звук, красно-синие световые акценты, анимация точек, виброотклик и попытка включения гироскопа.
- Совместимость нового JS со старой разметкой кнопок `data-effects` и `data-sound`, чтобы смешанная загрузка версий не останавливала весь тур.

## 7. Что не завершено

### Критически важно

1. Нет реальных 360°-съёмок автомобилей станции.
2. Классы B и C используют одну и ту же демонстрационную внешнюю панораму и одну и ту же демонстрационную внутреннюю панораму.
3. Перечень оборудования и описания точек являются демонстрационной структурой; их нужно сверить с фактической комплектацией двух конкретных автомобилей.
4. HTTPS на тестовом адресе не подтверждён и при последней проверке возвращал 502. Без HTTPS не будет полноценного WebXR, а часть сенсорных API может быть недоступна.
5. Опубликованная папка на Beget могла содержать смешанные версии HTML/JS/CSS. Нужна чистая сверка каждого опубликованного файла с `dist`.
6. Юридические тексты, сведения об операторе сайта, права на логотип и фотографии не утверждены станцией или юристом в рамках проекта.

### Качество и сопровождение

- Нет автоматизированных unit-, e2e-, visual regression- и accessibility-тестов.
- Нет подтверждённого Lighthouse/axe-аудита.
- Нет матрицы реальных проверок Chrome, Яндекс Браузера, Firefox, Safari iOS, Android и VR-гарнитуры.
- CSS частично минифицирован и содержит слои старых правил и новых переопределений; его сложно сопровождать.
- `build_pages.py` содержит длинные HTML-строки; архитектура генератора пригодна для небольшого сайта, но неудобна для редакторской работы.
- Нет CMS или панели управления; новости меняются только в коде.
- Новости и даты захардкожены и требуют сверки с официальным сайтом.
- Нет автоматического импорта новостей с `rssmp.ru`.
- Изображения не имеют `srcset`, WebP/AVIF-вариантов и явных `width/height`.
- Две демонстрационные PNG-панорамы имеют размер около 2,3 МБ каждая и разрешение 1774×887 — это недостаточно для финального премиального 360°-тура.
- Нет многоуровневой загрузки панорам, тайлов или выбора качества по устройству.
- Нет офлайн-режима/service worker.
- Не проверена работа сайта при 200% масштабе текста и в старых браузерах.
- Не утверждены финальный домен, canonical URL, sitemap и правила индексации.

## 8. Важное уточнение о «5D»

Веб-сайт не может обеспечить физический 5D-эффект без внешнего оборудования: кресел, ветра, запахов и других исполнительных устройств. Реализованный режим — браузерная имитация присутствия.

На компьютере доступны визуальные эффекты и звук. На телефоне дополнительно могут работать гироскоп и вибрация. Поддержка вибрации отсутствует, например, в некоторых версиях Safari/iOS. Web Audio запускается только после действия пользователя. Не заявляй, что все эффекты одинаково работают на каждом устройстве.

Для публичного сайта комиссии рассмотри профессиональное название «Эффект присутствия» вместо «5D», но не меняй его без согласования с владельцем проекта.

- Предложить минимальную понятную архитектуру сопровождения, не вводя тяжёлый фреймворк без необходимости.

### Все страницы и тексты

Проверить отдельно:

- `/`;
- `/about/`;
- `/patients/`;
- `/news/`;
- `/tours/`;
- `/gallery/`;

На каждой странице проверить смысл, орфографию, пунктуацию, единообразие названий, длину строк, повторения, актуальность фактов, телефонные ссылки, электронную почту, адрес, внешние ссылки, метаданные и мобильное отображение.

Не подтверждай медицинские, юридические или организационные сведения только по исходному коду. Составь перечень данных, которые станция должна письменно утвердить.

Проверить:

- мобильное меню, закрытие и возврат фокуса;

- галерею, стрелки клавиатуры, подписи и закрытие;
- фильтры новостей и сообщение для screen reader;
- копирование адреса при разрешённом и запрещённом Clipboard API;
- все состояния hover/focus/active/disabled;
- телефонные и внешние ссылки;
- отсутствие горизонтального скролла.

### Доступность

- Клавиатурная навигация без мыши.
- Видимость фокуса.
- Контраст всех состояний.
- Иерархия заголовков и landmarks.

- Настроить HTTPS, корректный редирект HTTP→HTTPS и только после проверки рассмотреть HSTS.
- Не добавлять формы обратной связи, аналитику, cookies, CMS или серверную обработку персональных данных без отдельного проекта безопасности и правового основания.
