# Публикация на Beget

## Где что лежит

| Путь | Назначение |
|---|---|
| `build_pages.py` | Генератор: тексты страниц, поисковый индекс, версии файлов |
| `shell.html`, `home.html` | Общая оболочка и главная страница |
| `static/` | Редактируемые исходники: `style.css`, `app.js`, `tour-viewer.js`, `assets/`. Папка `static/vendor/` — готовая сборка библиотек тура, вручную не редактируется |
| `vendor-src/` | Исходник сборки библиотек 3D-тура: Photo Sphere Viewer 5.15.1 и three.js 0.185.1 (лицензия MIT). Пересборка: `cd vendor-src && npm install && npm run build` → `static/vendor/psv.js`, `psv.css`, `LICENSES.txt` |
| `beget.htaccess` | Исходник `dist/.htaccess` |
| `source-assets/` | Исходники изображений, которые не публикуются: эмблема 512 px (на сайте — `assets/logo.png`, 160 px) и мастер-файлы панорам в `source-assets/panoramas/` |
| `make_panorama_variants.py` | Готовит панорамы тура для сайта: JPEG, превью и тайлы (нужна библиотека Pillow) |
| `check_deploy.py` | Сверка опубликованного сайта с `dist` |
| `GITHUB_PAGES.md` | Публикация на GitHub Pages (сборка `RSSMP_TARGET=github`) |
| `dist/` | Результат сборки. **Не редактируется вручную** и пересоздаётся при каждой сборке |
| `tests/` | Автоматические проверки (`tests/README.md`) |

## Демонстрационная сборка

```bash
python3 build_pages.py
```

Сборка закрыта от поисковых систем, пока тексты, права на материалы и реальные панорамы не утверждены станцией.

## Публичная сборка

```bash
RSSMP_PUBLIC=1 RSSMP_BASE_URL=https://example.ru python3 build_pages.py
```

Замените `https://example.ru` на утверждённый домен. Будут созданы `robots.txt` с разрешением индексации, `sitemap.xml` и canonical-ссылки.

## Загрузка

1. Соберите сайт одной из команд выше. `.htaccess` копируется в `dist` автоматически.
2. Упакуйте **содержимое** `dist`, а не саму папку.
3. В файловом менеджере Beget **удалите старое содержимое** `public_html` (или переименуйте его), затем распакуйте архив в `public_html`. Частичная замена файлов приводила к смешанным версиям страниц.
4. Проверьте главную, прямые ссылки на разделы, `/tours/` и несуществующий адрес (должна открыться страница 404).
5. Сверьте сервер с `dist`:

   ```bash
   python3 check_deploy.py http://dexaur9j.beget.tech
   ```

   Все строки должны быть `SAME`. `MISSING` — файла нет на сервере, `DIFF` — там старая версия. 24.09.2026 проверка показала: загружены только файлы из корня `dist`, а папка `assets` и подпапки страниц (`about`, `patients` и др.) остались старыми. Поэтому на новой главной не было эмблемы, а на телефонах — фото «Практическое занятие».

При загрузке через файловый менеджер Beget убедитесь, что распаковываются **папки** (`assets`, `about`, `contacts`, `gallery`, `news`, `patients`, `privacy`, `tours`) с заменой существующих файлов, а не только файлы из корня.

## Кэширование на Beget

Проверка 24.09.2026 показала: CSS, JS и изображения на Beget отдаёт nginx с `Cache-Control: max-age=604800` (7 дней), правила `.htaccess` для этих файлов не применяются. Поэтому генератор добавляет к каждой ссылке на CSS, JS и изображение `?v=<хэш содержимого>`: изменённый файл получает новый адрес и загружается сразу, без ожидания 7 дней. Не удаляйте эти параметры вручную.

## HTTPS

Для гироскопа, WebXR и системного буфера обмена нужен HTTPS. На 24.09.2026 тестовый адрес по HTTPS сбрасывал соединение.

1. В панели Beget, в настройках домена, выпустите бесплатный SSL-сертификат (Let's Encrypt). Возможность выпуска для технического адреса `*.beget.tech` нужно уточнить в поддержке Beget; для официального запуска нужен собственный домен станции.
2. Дождитесь, пока `https://домен/` откроется без предупреждений.
3. Только после этого включите перенаправление HTTP → HTTPS в панели Beget или раскомментируйте блок `RewriteRule` в `beget.htaccess` и пересоберите сайт.
4. HSTS (`Strict-Transport-Security`) включайте последним, когда HTTPS стабильно работает на всех адресах.

## Панорамы 3D-тура: режимы

Режим задаёт `TOUR_PANORAMAS` в `build_pages.py`; `python3 build_pages.py` печатает его в строке `tour: …`.

| Режим | Когда | Что на странице |
|---|---|---|
| `vehicles` — **сейчас** | у B и C свои настоящие снимки снаружи и в салоне | Выбор «Класс B / Класс C». У каждого класса — двор станции, вид снаружи, медицинский салон: 6 сцен, 27 точек. Двор показывается, если его панорама задана у обоих классов |
| `demo` | хотя бы один файл B/C демонстрационный или файлы B и C совпадают | Один демонстрационный тур без выбора класса, с пометкой, что это не съёмка станции |

- Классы по указанию владельца: кадры 0067–0074 — реанимобиль класса C, кадры 0075–0085 — автомобиль класса B.

### Как заменить или добавить съёмку

1. Положите исходники (PNG, JPEG или TIFF, 2:1) в `source-assets/panoramas/`, например `tour-b-exterior.jpg`, и выполните `python3 make_panorama_variants.py`. В `static/assets/` появятся `<имя>.jpg` (не шире 8192 px), `<имя>-preview.jpg` (1024 px) и папка `tour-tiles/<имя>-<хэш>/` с тайлами. Превью показывается сразу, затем браузер загружает только видимые тайлы нужной детализации; полный JPEG используется в режиме VR.
2. Укажите файлы в `TOUR_PANORAMAS` (`b-yard`, `b-exterior`, `b-interior`, `c-yard`, `c-exterior`, `c-interior`) и выполните `python3 build_pages.py`.
3. Положение точек (`yaw`, `pitch`) в `static/tour-viewer.js` выставьте по оборудованию на новых снимках: `yaw = (x / ширина − 0,5) · 2π`, `pitch = (0,5 − y / высота) · π`. Точки демонстрационных панорам — отдельно, в `demoScenes`.

Выбор классов включается, только если файлы B и C различаются **по содержимому** — и снаружи, и в салоне — и ни один из них не демонстрационный. Иначе остаётся демонстрационный режим (`tour: demo`). Старые ссылки вида `/tours/#b-interior` работают в обоих режимах.

Требования к съёмке — в `AUDIT_REPORT.md`, раздел «Стратегия 360°-панорам». Съёмка автомобилей станции подготовлена в 8192×4096. Демонстрационные панорамы (1774 px) остаются только для демо-режима.
